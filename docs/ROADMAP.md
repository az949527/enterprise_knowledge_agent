 
# Roadmap

## 总目标

做一个本地可运行、可展示的企业知识库 Agent 工作台：

- 能上传或读取文档。
- 能基于文档问答。
- 回答有引用来源。
- 每次回答有 Agent Trace。
- 有评估集和指标。
- 能接入至少一个业务样板。

## 阶段 1：基础知识库问答

周期：1 到 2 周。

目标：先让系统能稳定回答文档问题。

产出：

| 结果 | 标准 |
|------|------|
| Demo 文档集 | 至少 10 篇 txt/md/pdf 中的一类 |
| 文档分块脚本 | 能输出 chunk 数量和 chunk 内容 |
| 向量索引 | FAISS 本地索引可保存和加载 |
| 问答脚本/API | 输入问题，返回答案 |
| 引用来源 | 每个答案显示 2 到 5 条引用 chunk |

量化指标：

| 指标 | 目标 |
|------|------|
| 文档数量 | 10 篇 |
| 测试问题 | 20 个 |
| 平均响应时间 | 本机 10 秒内 |
| 回答带引用比例 | 100% |

## 阶段 2：RAG 评估

周期：1 到 2 周。

目标：不再凭感觉判断效果。

产出：

| 结果 | 标准 |
|------|------|
| `evals/eval_dataset.json` | 至少 30 条问题 |
| 标准答案或关键点 | 每条问题有参考要点 |
| 标准引用 | 每条问题标注应该命中的文档或 chunk |
| 评估脚本 | 一条命令跑完整评估 |
| 评估报告 | 输出 markdown/csv |

指标：

| 指标 | 含义 |
|------|------|
| Recall@5 | 正确文档是否出现在前 5 个检索结果 |
| 引用命中率 | 回答引用是否来自正确文档 |
| 答案完整度 | LLM 或规则按 0 到 5 分打分 |
| 幻觉率 | 是否出现文档外编造 |
| 平均延迟 | 每个问题耗时 |

初始目标：

| 指标 | 目标 |
|------|------|
| Recall@5 | >= 70% |
| 引用命中率 | >= 70% |
| 答案完整度 | >= 3.5 / 5 |
| 幻觉率 | <= 20% |

## 阶段 3：Agent Trace

周期：1 到 2 周。

目标：每次回答都能复盘，不做黑箱 Agent。

产出：

| 结果 | 标准 |
|------|------|
| Trace 记录 | 每次问答保存完整步骤 |
| Trace 查看 | CLI 或页面能查看单次 trace |
| 检索记录 | 保存 query、top chunks、score |
| 工具调用记录 | 保存调用了哪些工具 |
| 答案证据链 | 能看到证据如何进入最终答案 |

最小 Trace 结构：

```text
用户问题
-> query 改写
-> 检索 top_k
-> rerank 结果
-> 选择引用
-> 生成答案
-> 质量自检
-> 最终回答
```

量化指标：

| 指标 | 目标 |
|------|------|
| Trace 覆盖率 | 100% |
| 单次 Trace 步骤 | 至少 5 步 |
| 可复盘问题数 | 30 条评估问题都能复盘 |

## 阶段 4：金融投研样板

周期：2 周。

目标：把 `investment_agent` 变成平台的一个业务案例。

产出：

| 结果 | 标准 |
|------|------|
| 投研文档库 | 上传宏观材料、研报摘要、政策文本 |
| 投研问答 | 能回答资产配置原因 |
| 投研报告生成 | 基于文档 + 回测结果生成报告 |
| 来源追溯 | 核心观点能追溯到 chunk |
| 回测结果附件 | 报告展示收益、回撤、权重 |

量化指标：

| 指标 | 目标 |
|------|------|
| 投研材料 | 20 篇 |
| 投研问题 | 30 个 |
| 月度报告 | 至少 1 份 |
| 报告引用覆盖率 | 核心观点 100% 有引用 |
| 回测图表 | 至少 3 张 |

## 阶段 5：可展示工作台

周期：2 到 3 周。

目标：形成可以演示的界面。

页面：

| 页面 | 内容 |
|------|------|
| 文档管理 | 上传、列表、删除、分块状态 |
| 知识库问答 | 问题、答案、引用 |
| 评估面板 | 指标、历史评估结果 |
| Agent Trace | 展示完整执行过程 |

产出：

| 结果 | 标准 |
|------|------|
| 本地页面 | 浏览器可打开 |
| 演示流程 | 5 分钟内讲清楚 |
| 截图材料 | 至少 6 张 |
| 项目 README | 架构、功能、运行方式完整 |
| Demo 视频 | 可选，1 到 3 分钟 |

## 持续迭代机制

| 周期 | 固定产出 |
|------|----------|
| 每周 | 新增 10 个评估问题，跑一次评估 |
| 每两周 | 优化一个指标，例如 Recall、延迟、幻觉率 |
| 每月 | 做一个业务样板报告 |
| 每季度 | 总结一次版本演进和指标变化 |
